What the JuDDGES HiTL Tool Does

JuDDGES helps researchers search appeal judgments, collect documents into projects, review model-suggested codes, and export structured research data. The usual workflow is:

Create or select project Search documents Review model suggestions Sync Hypothesis Export final data

Correct model suggestions do not need extra comments. Human review is only needed when a suggestion is wrong, incomplete, missing, or needs a new code.

Getting Started

  1. Log in to https://juddges.org/.
  2. Use My Projects to create or select the project you are working on.
  3. Open Coding Scheme if you need to check variable descriptions and examples.
  4. Use Search Documents to find judgments and add relevant documents to your project.
  5. Open a document to inspect available human/model values and any disagreement flags.
  6. Use Extract Data when the project is ready for export.

Reading the Document Detail Page

The document page shows codes identified for the judgment. The main value column prefers human-normalized values, then human raw values, then model-normalized values, then model raw values. If a variable has more than one applicable normalized value, all values are shown.

Use Show details to inspect the human and model values separately. If human and model values are at least 80% similar after normalisation, the page treats them as a close match rather than a disagreement.

Human-in-the-Loop Review

HiTL review uses Hypothesis as the annotation layer. The JuDDGES tool copies model suggestions into the selected project review group, reviewers make corrections in Hypothesis, and the tool imports approved reviewer work back into the project during sync.

  1. Open Hypothesis Tool for browser setup, login, group joining, and review-access instructions.
  2. Open the document from JuDDGES using Open Document.
  3. Activate the Hypothesis extension and select the project review group, not Public.
  4. Read each model suggestion against the judgment text.
  5. Only add a reply or annotation when the model suggestion is wrong, incomplete, or missing.
  6. Run Sync Project Review Group after review work has been saved in Hypothesis.
If Hypothesis login does not work on a National Archives judgment page, open google.com, activate the Hypothesis extension there, log in, then return to the judgment page.

How to Record Review Decisions

Situation What to do What happens in export
The model suggestion is correct Do nothing!!! Leave the model suggestion unchanged. Do not add an accept comment or duplicate annotation. It is treated as an implicit accept.
The model suggestion is wrong but you are unsure/don't know the correct answer Reply to the model suggestion with reject, or add the tag review:reject. Use this when the value should not be exported but you cannot provide a replacement. The rejected model value is no longer visible/used.
The model suggestion is wrong and you know the correct answer Reply to the model suggestion with the corrected value. This is preferred because the tool can inherit the correct field from the original suggestion. The human (your) correction takes priority over the model value.
You want to add a new code for the model to learn Highlight the text exemplifying the code, create a new annotation, enter the value if needed, and add the correct field tag, for example field:Sentence or Sentence. Save it in the project review group. The new human annotation is included if the reviewer is approved by the tool administrator.

Sync and Export

  1. Select the correct project in My Projects.
  2. Open Hypothesis Tool.
  3. Use Sync Project Review Group to copy missing model suggestions and import approved human review annotations.
  4. Refresh document pages if you want to inspect imported values.
  5. Use Extract Data and choose Final reviewed dataset for normal HiTL output.

The final reviewed dataset prioritises human corrections, excludes rejected model suggestions, and treats unchanged model suggestions as implicit accepts.

Good Review Habits

  • Always check that Hypothesis is using the project review group, not Public.
  • Read the underlying judgment text before rejecting or correcting a suggestion.
  • Leave correct suggestions unchanged.
  • Prefer replying to an existing model suggestion when rejecting or correcting.
  • Use the correct field tag when creating a brand-new annotation.
  • Run sync again before exporting if new review work has been added.

Frequently Asked Questions

I cannot see annotations in Hypothesis.

Check that you have joined the review group, opened the Hypothesis extension, and selected the project review group in the Hypothesis sidebar. Ask an admin to run sync if suggestions have not yet been copied into the group.

I submitted my Hypothesis username. Why are my annotations not imported?

Your request may still be pending. An admin must approve your Hypothesis username before your annotations are imported into the reviewed dataset.

Should I mark every correct suggestion as accepted?

No. Correct model suggestions are accepted implicitly by leaving them unchanged.

What if I made a mistake when rejecting and/or correcting a model suggestion, or when adding a new code?

Just delete the comment and the model will revert back to before. Then run sync again so the tool imports the current Hypothesis state.

What if I type the wrong tag?

Edit or delete the Hypothesis annotation, then save it with the correct field tag and run sync again. If the tag is genuinely new, an administrator may need to add or approve it in the Coding Scheme.

What should I export?

For normal research use after review, choose Final reviewed dataset. Use human-only, gold-only, model-only, or all-source exports only when auditing or troubleshooting.
