What JuDDGES Does

JuDDGES helps researchers search Court of Appeal judgments, collect documents into projects, inspect extracted coding values, review model suggestions, add extension codes, and export structured research data.

Create or select project Check coding scheme Search documents Inspect extracted values Review with Hypothesis Export data

Basic Workflow Without HiTL

  1. Log in to https://juddges.org/.
  2. Open My Projects. Create a project, or select an existing project and choose Activate Project.
  3. Use View/Edit Project to open the Project page, edit details, and see documents already added.
  4. Open Coding Scheme before searching. Use View guidance to check code descriptions, possible values, and examples.
  5. Open Search Documents, enter a keyword, choose where to search, and use filters such as scope, coding source, or code.
  6. Add relevant results to your project. If there are several result pages, add documents from each page you need.
  7. Open a document from search results or from the Project page to inspect citation details, excerpt, and extracted codes.
  8. When ready, use Extract Data to export all codes, base codes, or extension codes in long or wide CSV format.

Project Page

The Project page is different from My Projects. It is where you view/edit one selected project, inspect the project document list, run Sync Project, and, for reviewers/admins, run Propagate Approved Tags.

  • Edit project details: update the project name and description.
  • Documents in project: open documents already added to the project.
  • Sync Project: sync all documents in the project with the selected Hypothesis review group.
  • Propagate Approved Tags: use approved extension-code examples to create model suggestions across the project for human review.

Reading the Document Detail Page

The document page shows codes identified for the judgment. The main value column prefers human-normalized values, then human raw values, then model-normalized values, then model raw values. If multiple normalized values apply, all values are shown.

  • Use Show details to compare human and model values separately.
  • The similarity score is calculated from normalized values.
  • A score of at least 80% is treated as a close match rather than a disagreement.
  • Use Open Document to open the full judgment for Hypothesis review.
  • Use Sync This Document after making Hypothesis changes on this one document.

Set Up Hypothesis for HiTL Review

HiTL review uses the Hypothesis browser extension as the annotation layer. A separate Chrome profile is recommended so review work is isolated from personal or work browsing accounts.

  1. Use Chrome, or install it from Google Chrome.
  2. Create a Guest Chrome profile or a dedicated review profile.
  3. Install the Hypothesis extension or bookmarklet from the Hypothesis Tool page.
  4. If Chrome asks whether the extension can access website data, allow it. For tighter control, set site access to When you click the extension.
  5. Open Hypothesis Tool, join the review group, and request/manage review access if needed.
  6. Always select the project review group in Hypothesis, not Public.
If Hypothesis will not activate on a National Archives judgment page, open google.com, activate Hypothesis and log in there, then return to the judgment page and select the project review group.

Viewing Hypothesis Annotations

  1. On the Project page, use Sync Project to copy model suggestions and gold standard items into the project review group.
  2. Open a document from the Project page or Search Documents.
  3. Click Open Document on the document detail page.
  4. Click the Hypothesis h. button in the browser, then open the sidebar.
  5. Check that the correct review group is selected.
  6. Click an annotation card or highlighted text to focus on one annotation. Use Clear filter in Hypothesis to show all annotations again.

Some annotations appear as page notes when the tool cannot uniquely anchor the exact text in the judgment. These should still be reviewed against the judgment text.

How to Record Review Decisions

Situation What to do in Hypothesis What happens in JuDDGES
The model suggestion is correct Do nothing. Leave the model suggestion unchanged. The unchanged model suggestion is treated as an implicit accept.
The model suggestion is wrong and you do not know the correct answer Reply with reject, or add the tag review:reject. The rejected model value is excluded from the reviewed output.
The model suggestion is wrong and you know the correct answer Reply to the model suggestion with the corrected value. You may use corrected: value. Your correction takes priority over the model value.
A useful code/value is missing Highlight the relevant text, create a new annotation, add the value if needed, and add a field tag such as field:OffenceLocation. The tag appears as a pending reviewer tag until it is approved or mapped in the Coding Scheme.

After rejecting, correcting, or adding annotations, run Sync This Document from the document page or Sync Project from the Project page so JuDDGES imports the latest Hypothesis work.

Extension Codes and Propagation

  1. Create new extension-code examples in Hypothesis by highlighting text and adding a clear field tag.
  2. Sync the document or project so the new tag appears in Coding Scheme as a pending reviewer tag.
  3. Approved extension codes remain separate from the locked Original Base Codelist.
  4. Reviewers/admins can use Propagate Approved Tags on the Project page to create model suggestions for similar values in other project documents.
  5. Propagated suggestions are still suggestions. Reviewers should accept implicitly, correct, or reject them through the normal HiTL workflow.

Sync and Export

  1. Use Sync This Document when you have only changed one document.
  2. Use Sync Project when you need to prepare or refresh all documents in the selected project.
  3. Refresh document pages if you want to inspect imported values after sync.
  4. Use Extract Data and choose Final reviewed dataset for normal HiTL output.

The final reviewed dataset prioritises human corrections, excludes rejected model suggestions, and treats unchanged model suggestions as implicit accepts.

Good Review Habits

  • Always check that Hypothesis is using the project review group, not Public.
  • Read the underlying judgment text before rejecting or correcting a suggestion.
  • Leave correct suggestions unchanged.
  • Prefer replying to an existing model suggestion when rejecting or correcting.
  • Use clear field tags when creating brand-new annotations.
  • Only correct a suggestion when you are confident in the answer.
  • Run sync again before exporting if new review work has been added.

Frequently Asked Questions

I cannot see annotations in Hypothesis.

Check that you have joined the review group, opened the Hypothesis extension, and selected the project review group in the Hypothesis sidebar. Run Sync Project if suggestions have not yet been copied into the group.

I submitted my Hypothesis username. Why are my annotations not imported?

Your request may still be pending. An admin must approve your Hypothesis username before your annotations are imported into the reviewed dataset.

Should I mark every correct suggestion as accepted?

No. Correct model suggestions are accepted implicitly by leaving them unchanged.

What if I made a mistake?

Edit or delete the Hypothesis reply/annotation, then run sync again so JuDDGES imports the current Hypothesis state.

What if I type the wrong tag?

Edit or delete the Hypothesis annotation, then save it with the correct field tag and run sync again. If the tag is genuinely new, it may need to be approved or mapped in the Coding Scheme.

What should I export?

For normal research use after review, choose Final reviewed dataset. Use human-only, gold-standard-only, model-only, or all-source exports only when auditing or troubleshooting.
